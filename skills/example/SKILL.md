# example — пример скилла add-on'а

Это **заготовка** скилла формата [AD-046](https://gitverse.ru/itphx/synth).
Скилл — декларативный контент для агента Synth (не код сервиса): инструкция, что и
как делать при работе с вашим add-on'ом. Тело загружается только при вызове —
progressive disclosure.

## Когда применять

Опишите триггер: при каких запросах агент должен использовать этот скилл
(например, «публикация материала», «приём события из мессенджера»).

## Что делает скилл

1. **Собрать входные данные** — из каких источников, какие поля обязательны.
2. **Вызвать инструменты add-on'а** — MCP-тулы (имена вида
   `{serverName}_{tool}`) и/или API v2 add-on'а.
3. **Обработать результат** — что вернуть пользователю, какие ошибки учесть.

## Инструменты

Опишите MCP-тулы/эндпоинты add-on'а, которые скилл использует:

| Инструмент | Назначение |
|---|---|
| `example_ping` | Пример MCP-тула шаблона (проверка связи) |

## Границы

- Скилл **не пишет** в хранилище add-on'а в обход его API/MCP.
- Секреты (токены) — вне git.
- Ничего не публиковать/не отправлять без явного подтверждения, если это
  действие необратимо.

> Supporting-файлы (справочники, шаблоны) можно класть рядом со `SKILL.md` и
> ссылаться на них относительными путями: например, `reference/tools.md`.
